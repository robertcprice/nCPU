# Drift-Proof Emergent NL Grounding

*How nsynth's natural-language front door stays provably in sync with the engine's real
capabilities — and refuses, rather than fabricates, what it cannot do.*

Status: design note capturing the architecture built across the NL-BRIDGE / UNWALL work
(canonical, 2026-06). Audience: anyone evaluating the agent or extending the NL layer.

---

## The problem this solves

Most NL→code systems are LLM-generators: they emit plausible code and *hope* it is correct.
Two failure modes follow — (a) **hallucination**: claiming a capability the system does not
have; (b) **drift**: the surface vocabulary and the implementation diverge over time, so the
docs/prompt promise things the code no longer does.

nsynth takes the opposite stance: **a capability cannot be *spoken* unless a tested
implementation backs it, and the spoken vocabulary is *derived from* the implementation —
so it cannot drift.**

## The three load-bearing ideas

### 1. The vocabulary IS the engine's symbol table (auto-mined, not hand-listed)
`capability_miner.rs` reflects the engine's own operator surface — `string_synth`'s `SExpr`
operator enum, `array_transform`'s `ReorderKind` / `ElementMapKind`, the stateful-reducer op
set, the tensor forward ops — into the NL capability registry. Each entry's `example_cases`
are **generated by running the real evaluator** (proof: the mined `lowercase(" Hello ")` row
is `" hello "` — whitespace preserved, which no hand author would do). Add a `pub fn`/operator
to the engine, re-mine, and it becomes NL-reachable automatically. The 31-op hand registry is
a legacy seed, not the ceiling.

### 2. Emergence is enforced by the compiler
Each mineable family has an **exhaustive-match guard** (`mineable_string_ops_exhaustive`,
`mineable_element_map_ops_exhaustive`, `forward_op_calls_compile_against_engine`, …). Add an
operator variant to the engine and forget to map it → **the build fails**. So the NL surface
*cannot* silently lag the implementation. Drift is a compile error.

### 3. Type-aware routing + honest fail-closed gates
- `op_role` is a `TypeClass` lattice (`coding_requirements.rs`) — scalar/collection/tensor/
  struct — so f64/string/array/tensor ops route to the synthesis families that already handle
  them (`search_float`, `string_synth`, `array_transform`, tensor codegen) instead of being
  dropped to "unknown".
- The fail-closed gate (`unsound_confident_solve` / `fail_closed_reason`) **refuses** a request
  whose operator does not confidently resolve or whose operand types mismatch — emergently,
  from resolver scores + signatures, **not a phrase blocklist**.
- Stubs are never claimed: tensor *training* refuses (`Trainer::train` is a no-op), `parse a
  csv` refuses (no string→struct synthesis yet), "quantum" refuses (no primitives exist).

## What "verified" means here

Every synthesized program is admitted **only** by `verify_problem_code_strict` — it runs the
candidate against the examples **and fresh holdouts** (inputs disjoint from the solver's
sampling window). Reference-intake proves this sharply: `"behaves like fn f(x){x*x-x}"` yields
`(-1*x)+(x*x)` (a *different form*, not a copy) that agrees with the reference on `[-500..4321]`
— well outside the `[-64,64]` the solver sampled. That is real generalization, gated by a real
oracle, not memorization.

Multi-file output is gated on an actual `cargo check`; tensor codegen is gated on a real
compile against the `mog_synth` crate. Success is reported **only** on a clean compile.

## The capability surface (NL-reachable, all test-grounded)

`i64` · `f64` · `string` (transforms) · `array` map/reduce · **stateful** per-tick updates
(running max/min — state a stateless reduce can't express) · **cooperating functions**
(B genuinely calls A across modules, crate compiles) · **synthesis-from-reference** ·
**tensor forward** (relu/sigmoid/softmax/tanh/transpose/matmul/add/sub/mul/div/sqrt) ·
**learn-on-the-fly** (teach an op by examples/composition, regression-gated, reused across
processes).

Honestly *not* claimed: tensor training (no-op), real network I/O (stubbed), threading
(`parallel for` is sequential), `db`/sql (in-memory), quantum (absent). The agent refuses
these rather than fabricate.

## Why this is novel + valuable

- **Drift-proof**: the surface is the symbol table; divergence is a compile error. Unique vs
  prompt/registry-maintained NL interfaces that rot.
- **Honest by construction**: refuses out-of-domain instead of hallucinating — the property
  that makes a synthesis agent trustworthy enough to ship.
- **Self-growing**: adding engine capability auto-extends the NL surface (re-mine), no
  hand-maintenance — and the same `capability_miner` generalizes to expose *any* Rust crate's
  pure-fn surface as verified NL-callable bindings.

## One-line summary

> An NL programming interface that **cannot drift from its implementation** (the vocabulary is
> the compiler-checked symbol table) and **refuses what it cannot verify** (every result passes
> a strict holdout/compile oracle) — the trust properties LLM codegen lacks.
