PROJECT OVERVIEW
================================================================================

Current State: nsynth synthesizes MONOLITHIC functions
Goal:          Synthesize COMPOSED functions (filter → map → reduce chains)

Example Problem: filter_sum_positive([1, -2, 3, -4, 5]) → 9

Current Approach (Monolithic):
  fn filter_sum_positive(arr: [i64]) -> i64 {
    result: i64 = 0
    i: i64 = 0
    while i < len(arr) {
      if arr[i] > 0 { result = result + arr[i] }
      i = i + 1
    }
    return result
  }

Stage 6 Approach (Composed):
  fn filter_helper(arr: [i64]) -> [i64] { /* filter arr > 0 */ }
  fn sum_helper(arr: [i64]) -> i64 { /* sum array */ }
  fn filter_sum_positive(arr: [i64]) -> i64 {
    filtered: [i64] = filter_helper(arr)
    return sum_helper(filtered)
  }

Benefits:
  ✓ Reusable library functions (filter, map, reduce, scan, sort)
  ✓ 2-3x faster synthesis (pattern matching vs. gradient descent)
  ✓ Clearer intent (code shows data flow)
  ✓ Potential for learned biases (good compositions cached)

ARCHITECTURE
================================================================================

5 New Components:

1. COMPOSITION LIBRARY (composition_lib.rs)
   - 9 hard-coded Mog templates: filter, map, reduce, scan, sort, etc.
   - Each fully verified, self-contained
   - Reused across many problems

2. PATTERN DETECTION (composition.rs)
   - Analyze problem I/O examples
   - Recognize filter/map/reduce/scan/sort patterns
   - Return confidence-sorted list of candidates

3. CODEGEN (composition.rs)
   - emit_inline_*: inlined loops (no function calls)
   - emit_composed_*_with_calls: multi-function code with calls
   - Both verified before returning

4. PROBLEM METADATA (benchmark.rs)
   - composition_allowed: bool
   - composition_hints: Vec<Pattern>
   - All 105+ factories updated

5. SEARCH TEACHER (solver/search.rs)
   - search_composition() added between enumerative and gradient
   - Gated on problem.composition_allowed
   - Returns SolveResult on success, None on failure (graceful)

PATTERN TYPES (6 Core Patterns)
================================================================================

FILTER: Array → Smaller Array
  Input:  [1, -2, 3, -4, 5]
  Output: [1, 3, 5]
  Logic:  Keep only elements where x > 0
  Detection: Output size < Input size, all outputs in input

MAP: Array → Array (Same Size)
  Input:  [1, 2, 3]
  Output: [2, 4, 6]
  Logic:  Apply function to each element (×2)
  Detection: |Input| == |Output|, outputs transform inputs

REDUCE: Array → Scalar
  Input:  [1, 2, 3, 4]
  Output: 10
  Logic:  Fold array with operator (sum, product, min, max)
  Detection: Input is array, output is scalar

SCAN: Array → Array (Cumulative)
  Input:  [1, 2, 3]
  Output: [1, 3, 6]
  Logic:  Cumulative fold (prefix sums)
  Detection: |Input| == |Output|, outputs are cumulative

SORT: Array → Array (Sorted)
  Input:  [3, 1, 2]
  Output: [1, 2, 3]
  Logic:  Reorder elements (ascending)
  Detection: Output is sorted(Input)

FINDALL: Predicate Search → Count/Indices
  Input:  [1, -2, 3]
  Output: 2 (count of x > 0)
  Logic:  Count or find indices of matches
  Detection: Input array, scalar/array output, filtering logic

KEY TECHNICAL DECISIONS
================================================================================

✓ Phase 1: Inline composition (no function calls)
  Why: Simpler to verify, more likely to succeed
  Cost: ~1 week

✓ Phase 2: Multi-function calls (composition chains)
  Why: Full generality, matches high-level intent
  Cost: ~1.5 days on top of Phase 1

✓ Hand-coded library templates (not synthesized)
  Why: Safe, reusable, verified once
  When: Deferred to Phase 3+

✓ Predicate inlining (not parameterized closures)
  Why: Simpler, avoids higher-order synthesis
  When: Upgrade to templates in Phase 2

✓ Pattern detection with confidence scoring
  Why: Ordered search (best-first)
  Cost: ~50-100ms per problem

✓ Graceful fallback (composition returns None, next teacher tries)
  Why: No regression risk
  Cost: Zero (if no pattern found)

================================================================================
RISKS & MITIGATION
================================================================================

Risk 1: Runtime doesn't support function calls
  Probability: Medium | Impact: High
  Mitigation: Test early (Day 7), fallback to inlining

Risk 2: Pattern detection overfits
  Probability: Low | Impact: Medium
  Mitigation: Validate on holdouts, require >0.7 confidence

Risk 3: Composition search explodes
  Probability: Medium | Impact: Medium
  Mitigation: Top 2-3 patterns only, early termination

Risk 4: Regression on existing benchmarks
  Probability: Low | Impact: High
  Mitigation: Run full suite after each change

Risk 5: Verify timeout on multi-function code
  Probability: Low | Impact: High
  Mitigation: 10s timeout per verify call
