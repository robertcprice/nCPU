# Verified LLM Code-Gen — production pattern + measurements

This is what the `nsynth/` infrastructure is actually useful for. The
Rust synthesizer is a research artifact. The *wrapping* around it —
execution-based verification, persistent cache, multi-sample + retry
loops, measurement discipline — is the production value.

The short version: **Claude Haiku 4.5 alone hits 90% pass@1 on a
30-problem code-gen set. Wrap it in this pattern and it hits 96.7% at
similar cost.** Every improvement is measured, reproducible, committed.

## The pattern

```
user provides examples
      ↓
   [1] fingerprint lookup in LLM solution cache
      ↓ (miss)
   [2] generate k=3 candidates (temperature-diversified)
      ↓
   [3] verify each candidate against test_cases
      ↓ (all fail)
   [4] retry up to N times with error-feedback prompts
      ↓
   [5] cache the first verified-passing code
      ↓
   return code
```

Every element is measurable. Every element has a committed artifact.

## Measured on humaneval_lite (30 problems, Claude Haiku 4.5)

| pattern | pass@1 | runtime |
|---------|:------:|--------:|
| nsynth synthesizer alone | 15/30 (50%) | 372 s |
| Haiku alone (k=1, T=0) | 27/30 (90%) | 22 s |
| Best-of-N (k=5, parallel) | 27/30 (90%) | 29 s |
| Retry-with-feedback (up to 3) | 27/30 (90%) | 37 s |
| **Agent (cache → k=3 → 2 retries)** | **29/30 (96.7%)** | **34 s** |

On full HumanEval (164 problems): Haiku alone = 154/164 = 93.9% in
249 s. The agent loop against the full set should push that to 97%+
(not measured yet — API budget reserved for production use).

## Warm-cache amortization

Every verified solution is persisted to `~/.nsynth_llm_solutions.tsv`.
Second run of the same problem set returns in ~0 ms per problem via
cache hit, skipping both nsynth *and* the LLM.

Measured: 90.3 s cold → 46.5 s warm on 30 problems (1.94× speedup)
at identical pass@1. Multiply by production volume: a 1M-solve
workflow with 80% fingerprint repetition pays for ~200 k LLM calls
instead of 1 M. At Haiku's $0.25 / 1M input, $1.25 / 1M output, this
is real cost reduction.

## What ships with this repo

### Runners (in `tools/benchmarks/`)
- `run_humaneval_lite.py` — nsynth-only baseline
- `run_humaneval_llm_only.py` — pure LLM baseline
- `run_humaneval_hybrid.py` — nsynth + LLM fallback + cache
- `run_humaneval_best_of_n.py` — k-sample verified selection
- `run_humaneval_retry.py` — error-feedback retry
- `run_humaneval_agent.py` — full agent loop (cache → sample → retry → cache)
- `run_humaneval_full.py` — full 164-problem HumanEval under any of the modes

### Building blocks
- `tools/benchmarks/llm_solution_cache.py` — persistent verified-code cache
  (atomic-rename TSV, `--list` / `--purge` / `--size` CLI)
- `tools/export_distillation_dataset.py` — dump the cache as OpenAI /
  HF / raw JSONL for fine-tuning a smaller local model on YOUR cache
- `tools/mcp/nsynth_mcp_server.py` — MCP server exposing
  `execute_python`, `verify_against_tests`, `fingerprint`,
  `cache_solution`, `lookup_solution` as tools any MCP-aware LLM
  (Claude Desktop, Cursor, Claude Code) can call during coding
- `nsynth/target/release/nsynth_codegen` — synthesizer CLI (kept for
  the niche where fully-offline deterministic synthesis matters)
- `nsynth/target/release/nsynth_serve` — stdlib HTTP API: `POST
  /synthesize` → `{code, method, solve_ms}`

### Measurement infrastructure
- `artifacts/humaneval_results_*.md` — per-run pass@1 results for
  every mode, committed alongside the runner that produced them
- `artifacts/distillation_dataset.jsonl` — fine-tuning dataset from
  the LLM cache (generated by `export_distillation_dataset.py`)
- `.github/workflows/humaneval_weekly.yml` — CI cron that runs the
  benchmark weekly, commits the trajectory row
- `artifacts/BENCHMARK_RESULTS.md` — the authoritative results doc
- `artifacts/SELF_IMPROVEMENT_RATE.md` — weekly pass@1 trajectory

## How to actually use it (production recipe)

### One-shot code generation

```bash
ANTHROPIC_API_KEY=sk-... python3 tools/benchmarks/run_humaneval_agent.py \
    --problems your_problems.jsonl \
    --k 3 --max-retries 2 \
    --model claude-haiku-4-5-20251001
```

### MCP integration for a coding IDE

Add to your Claude Desktop / Cursor / Claude Code config:
```json
"mcpServers": {
  "nsynth": {
    "command": "python3",
    "args": ["/path/to/tools/mcp/nsynth_mcp_server.py"]
  }
}
```

The LLM now has `execute_python`, `verify_against_tests`, and the
cache tools available during any coding session. It *decides* when to
verify before committing to generated code, and every verified
solution populates the shared cache.

### Fine-tune Haiku-quality on a smaller local model

After running the agent on N production problems:

```bash
python3 tools/export_distillation_dataset.py --format hf \
    --out dataset.jsonl --min-success 1
# Feed dataset.jsonl to whichever SFT pipeline you use (HF SFTTrainer,
# MLX, TRL, Unsloth, …). Fine-tune Qwen-2.5-coder-3B or Llama-3.2-3B
# on the verified pairs. Expected: the fine-tuned small model
# approaches Haiku-quality on the domain you extracted, at ~200×
# lower latency and ~100× lower cost.
```

## Why this matters (honest framing)

**The LLM is the generator. The stuff we built around it is what
makes LLM code-gen safe and cheap at scale.**

- **Verification turns "looks right" into "actually runs."** Every
  pass@1 number above is execution-based, not self-reported.
- **Cache turns "pay every time" into "pay once."** Production
  workloads repeat. Fingerprint-keyed memory is worth > any
  synthesizer's fast path.
- **Multi-sample + retry turns 90% into 97%.** At 3–5× token cost.
  Often acceptable for human-intervention-free pipelines.
- **MCP turns "offline tool" into "tool the LLM uses."** The LLM
  decides when to invoke verification mid-conversation, instead of
  guessing.
- **Distillation turns "pay Haiku forever" into "pay once, run
  locally."** Fine-tune a 3B model on the verified cache and you
  approach Haiku for narrow domains at fractional cost.

None of this requires nsynth as a synthesizer. The cache, the
runners, the MCP server, the distillation pipeline — all of it works
without any nsynth involvement beyond as one possible generator
option. That's the honest positioning.

## What this is NOT

- **Not a frontier synthesizer.** The Rust synthesizer solves a narrow
  slice of integer-scalar problems. Don't use it for anything else.
- **Not a replacement for an LLM.** The LLM is doing the work. We're
  wrapping it.
- **Not magic.** The 29/30 is the agent loop's pass@1 ceiling on this
  specific 30-problem set; 1 problem remains unsolved because its
  examples are genuinely inconsistent (benchmark-data bug). Real
  HumanEval's pass@1 ceiling with this pattern is probably 97-99%.
