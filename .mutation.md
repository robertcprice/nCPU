# nCPU Rust/GPU Mutation Brief

You are iterating on nCPU under strict Rust-first, GPU-side constraints.

## Core rule

Prefer Rust and GPU-side code paths, especially under:
- `kernels/rust_metal/`
- Metal launcher/runtime paths
- Rust-native benchmarking/reporting/utilities

Do not drift into Python-side feature work unless it is the thinnest possible glue and there is no practical Rust-side route.

## Current state

Recent work already landed:
- `ncpu_run` supports `--inspect` and `--json-report`
- distributed scheduling supports device affinity / required backends
- integrated schedule-and-run helper exists
- distributed device/benchmark demos exist
- cargo check for `ncpu_run` passes

## Next priorities

In order:
1. Extend `kernels/rust_metal/bin/ncpu_run.rs` with benchmark / repeat / aggregate reporting modes
2. Improve Rust-native reporting for ELF and boot-image runs
3. Add or improve Rust-side docs/examples for launcher/report workflows
4. Reduce friction in Rust/Metal usability before touching Python UX
5. Keep cargo check passing at every step

## Constraints

- Keep changes small and reversible
- Prefer additive flags/subcommands over invasive rewrites
- Do not break existing launcher behavior
- Do not add heavyweight new dependencies unless clearly justified
- Preserve or improve machine-readable output
- If you touch shared code, verify `cargo check --bin ncpu_run`
- If warnings are encountered, fix correctness issues first; warning cleanup is secondary unless local to your edits

## Good targets

- `kernels/rust_metal/bin/ncpu_run.rs`
- `kernels/rust_metal/src/*` only when necessary to support launcher/reporting/benchmarking
- `docs/` and `docs/plans/` for Rust launcher/reporting workflow notes
- `.hermes-lab/spec.yaml` and `.mutation.md` when tightening the experiment brief itself

## Avoid unless absolutely necessary

- new Python-only launcher features
- edits under `scripts/`, `tests/`, `training/`, or other Python-heavy surfaces unrelated to Rust launcher/reporting work
- cosmetic churn across unrelated files
- broad refactors with unclear validation
- touching active unrelated research worktrees

## Validation expectations

At minimum after each iteration:
- `cargo check --bin ncpu_run`

When applicable:
- run the new mode with `--inspect` or reporting flags
- ensure JSON output remains parseable and stable

## Preferred output style

- exact command examples
- concise human-readable summary
- structured JSON output for automation
- clear explanation of what changed and why

## Commit style

Use small focused commits, e.g.:
- `feat: add rust launcher benchmark mode`
- `feat: add aggregate json reporting for ncpu_run`
- `docs: add rust launcher workflow guide`
- `fix: keep ncpu_run reporting stable in inspect mode`
